# Documentation Consistency Verification Strategy

**Document ID:** DCV-001 | **Version:** 0.1.0 | **Status:** DRAFT | **Created:** 2026-04-23

This document defines verification strategy for consistency between LDIR documentation, formal specifications (Yellow Papers), architectural designs (Blue Papers), and implementation code. Automated and manual checks run in CI to detect drift.

---

## 1. Doc-Code Consistency

### DC-001: Public API Signatures Match Documentation

**Scope:** All `pub` items in `ldir-core` and `ldir-ir`.

**Rule:** `.docs/api_reference.md` must match signatures from `cargo doc --workspace --no-deps`.

**Verification:** Generate API surface via `cargo doc --output-format json` (nightly), extract `pub` signatures, diff against docs. Fail CI on mismatch.

**CI:** Every PR, blocking. **Traceability:** REQ-10.3.

---

### DC-002: Example Code in Docs Compiles

**Scope:** All ` ```rust ` code blocks in `docs/`, `.docs/`, `.specs/`.

**Rule:** Every tagged Rust code block must compile via `cargo test --doc`. Non-compiling blocks use ` ```rust,ignore `.

**Verification:** `cargo test --doc --workspace` plus `cargo check --example <name>` for `docs/examples/`.

**CI:** Test stage, blocking. **Traceability:** REQ-9.1.

---

### DC-003: Error Codes in Docs Match Implementation

**Scope:** Error variants in `ldir-core/src/error.rs` mapped to ERR-PARSE-001..003, ERR-VALID-001..007, ERR-COMP-001..002, ERR-EMIT-001.

**Rule:** Bidirectional match — every Blue Paper error code has an implementation variant and vice versa.

**Verification:** Extract variants via `grep`, extract codes from Blue Paper tables, bidirectional diff via `scripts/check_error_codes.sh`.

**CI:** PR check, blocking. **Traceability:** REQ-3.3.4, BP-IR-COMPILER-001 Section BP-5.

## 3. Drift Detection

### DD-001: Yellow Paper Theorem IDs Match Lean4 Proof Names

**Scope:** All theorem IDs in `yellow_paper_registry.toml` under `theorems` fields.

**Rule:** Every theorem ID (e.g., `THM-WF-SIR-001`) must have a corresponding Lean4 `theorem`/`lemma` in `.specs/02_architecture/proofs/LDIRProofs/`, traceable via BP-IR-COMPILER-001 Section BP-9.1 mapping.

**Verification:** Parse registry for IDs, parse `.lean` files for declarations, cross-reference. Track `sorry` count against Blue Paper.

**CI:** `lake build` + `scripts/check_theorem_ids.sh`, blocking. **Traceability:** REQ-4.4.1, REQ-4.4.2.

---

### DD-002: Blue Paper Interface Signatures Match Rust Implementations

**Scope:** IF-PARSE-001, IF-VALIDATE-001, IF-COMPILE-001, IF-EMIT-001 signatures.

**Rule:** Blue Paper Rust signatures must match actual `pub fn` signatures (names, parameter types, return types).

**Verification:** Extract via `rustdoc --output-format json`, parse Blue Paper code blocks, normalize and diff via `scripts/check_bp_signatures.sh`.

**CI:** PR check, blocking. **Traceability:** BP-IR-COMPILER-001 Sections IF-*; REQ-10.3.

---

### DD-003: Test Vector IDs Match Test File Names

**Scope:** All test vector IDs (TV-IR-001..005, TV-IR-A01..A09, TV-IR-B02, TV-IR-B04, TV-IR-P01..P03).

**Rule:** Every TV-ID must have a corresponding test function or data file. Report orphaned IDs and orphaned tests.

**Verification:** Extract IDs via regex from `.toml` specs, search test sources, cross-reference via `scripts/check_test_vectors.sh`.

**CI:** PR check, blocking. **Traceability:** BP-IR-COMPILER-001 Section BP-4.1; REQ-9.1, REQ-9.2.

## 3. API Documentation Generation

### AG-001: Workspace Documentation Build

**Scope:** All crates in the workspace.

**Rule:** `RUSTDOCFLAGS="--deny warnings" cargo doc --workspace --no-deps` must complete with zero warnings/errors.

**CI:** Doc build stage, blocking. **Traceability:** REQ-10.3.

---

### AG-002: Yellow Paper References in Doc Comments

**Scope:** All `pub` items in `ldir-core` and `ldir-ir`.

**Rule:** Doc comments on spec'd algorithm implementations must cite YP-ID and THM-ID (e.g., `/// [YP-IR-SEMANTICS-001], [THM-COMPILE-WF-001]`). Mapping maintained in `.docs/yp_impl_mapping.toml`.

**Verification:** `scripts/check_yp_refs.sh` verifies mapped functions have required references.

**CI:** Doc build stage, warning (non-blocking). **Traceability:** REQ-4.4.1; BP-IR-COMPILER-001 Section BP-4.2.

---

### AG-003: WCAG 2.1 AA Compliance for HTML Output

**Scope:** HTML output generated by `cargo doc`.

**Rule:** `cargo doc` HTML output must meet WCAG 2.1 Level AA (contrast, heading hierarchy, alt text, ARIA labels, keyboard nav).

**Verification:** `axe-core` audit against `target/doc/index.html`.

**CI:** Doc build stage, blocking. **Traceability:** REQ-3.2.3 (ATTACH_METADATA).

---

## 4. User Documentation

### UD-001: Getting Started Guide

**Scope:** `docs/getting-started.md`.

**Content:** Prerequisites, installation, first example (compile + PDF output), output verification, next steps.

**Verification:** Fresh-eyes manual review. Target: new user produces PDF in < 10 minutes. CI: link checking via `lychee`.

**Traceability:** REQ-10.1, REQ-11.1.1.

---

### UD-002: API Reference (Auto-Generated)

**Scope:** `.docs/api_reference.md`.

**Rule:** Auto-generated from `cargo doc`, wrapped in `<!-- AUTO-GENERATED:BEGIN/END -->` markers. CI regenerates and checks for unexpected diff.

**CI:** Doc build stage, warning on unexplained auto-gen changes. **Traceability:** DC-001.

---

### UD-003: Example Gallery

**Scope:** `docs/examples/` directory.

**Rule:** At least 5 working examples demonstrating core functionality. Each example must be a standalone Rust file that compiles and runs.

**Required Examples:** `hello-world.rs` (minimal PDF), `markdown-to-pdf.rs`, `tex-basic.rs` (amsmath/geometry), `custom-style.rs`, `incremental-edit.rs`.

**Verification:** Each runs via `cargo run --example <name>` in CI. Output artifacts verified non-empty. rustfmt compliant.

**CI:** Test stage, blocking. **Traceability:** REQ-1.2.1, REQ-1.2.2, REQ-11.1.2.

---

### UD-004: Migration Guide

**Scope:** `docs/migration-guide.md`.

**Rule:** A migration guide for future version upgrades. Must document breaking changes, deprecated APIs, and upgrade paths.

**Content:** SemVer 2.0.0 scheme (per BP-11), breaking change policy, deprecation timeline, upgrade instructions per version, template for new entries.

**Verification:** Link checking. Manual peer review per release. **Traceability:** BP-IR-COMPILER-001 BP-11.

### 5.2 Release Gate

All blocking checks (9 of 13) must pass before a release tag is created. Warning checks (AG-002, UD-001) generate advisory CI comments. Manual checks (UD-004, UD-005) require sign-off from the documentation lead.

## 6. Check Count

This document defines **13 consistency checks** across 4 categories: Doc-Code (3), Drift Detection (3), API Generation (3), User Documentation (4). All automated checks run in CI on every PR. Blocking checks must pass before merge; warning checks generate advisory comments. Manual checks are verified by designated reviewers at each release milestone.
