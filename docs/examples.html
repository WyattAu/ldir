# Getting Started with ldir

Welcome to this walkthrough of ldir, a document compiler that
turns Markdown (and other formats) into polished PDFs.

## Why an IR?

Most document tools parse and render in a single pass.
ldir instead builds a three-layer intermediate representation:

1. **S-IR** -- semantic structure (headings, paragraphs, math)
2. **L-IR** -- layout (page breaks, column flows, hyphenation)
3. **G-IR** -- rendering (glyph positions, draw commands)

This separation means you can optimize and verify each stage
independently.

## Quick Example

```markdown
# Hello
This becomes a PDF with one command.
```

```bash
ldc hello.md -o hello.pdf
```

That is it. No template files, no configuration needed.

# Performance Analysis of Line Breaking

## 1. Overview

This report measures the Knuth-Plass line-breaking algorithm
as implemented in the ldir layout engine.

## 2. Methodology

We measured line-breaking time on paragraphs of varying
length, running 1,000 iterations per data point.

```rust
use ldir_core::layout::linebreak::KnuthPlass;

fn measure(text: &str, width: f32) -> Duration {
    let kp = KnuthPlass::new(width);
    let start = Instant::now();
    for _ in 0..1000 {
        kp.break_lines(text);
    }
    start.elapsed()
}
```

## 3. Results

| Paragraph length | Time per call |
|-----------------|---------------|
| 100 words       | 12 us         |
| 500 words       | 58 us         |
| 1,000 words     | 124 us        |
| 5,000 words     | 610 us        |

## 4. Conclusion

The algorithm scales linearly with paragraph length,
confirming the expected $O(n)$ behavior.
